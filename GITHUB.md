# Обновления через GitHub

Код и выпуски программы размещаются в публичном GitHub-репозитории. База, фотографии, прайсы, резервные копии и локальные журналы туда не передаются. Публичные файлы нужны для обновления пользователей без входа в GitHub.

## Первое подключение

1. Репозиторий https://github.com/Michail-S1/viano-mebel создан в аккаунте Michail-S1.
2. Подготовить чистую папку с исходным кодом:
   python launcher/source.py --app-root . --output .qa/github-source
3. Создать публичный репозиторий viano-mebel и отправить туда подготовленные файлы.
4. Первая загрузка server.py в main автоматически запускает Publish update. После изменения VERSION следующий выпуск также запускается автоматически; доступны ручной запуск и тег v<версия>.
5. Дождаться успешного выпуска. В Releases появятся Viano-update-1.2.1.zip и latest.json.
6. Источник уже указан в программе по умолчанию. Для старой версии приложения можно указать его в окне «Обновить программу»:
   https://github.com/Michail-S1/viano-mebel/releases/latest/download/latest.json

До появления опубликованного выпуска эта ссылка не работает. Сохранённый пользователем источник update-source.json имеет приоритет над стандартным.

## Следующие версии

Внести изменение в код, увеличить VERSION, отправить изменения в main. Изменение server.py запускает выпуск; альтернативы — тег v<версия> или ручной запуск. GitHub Actions выполнит тесты каталога, проверку Windows-запуска и синтаксиса JavaScript, затем соберёт пакет только с программой и опубликует его. Можно использовать ручной запуск Publish update после изменения VERSION.

Новая версия сначала создаётся как черновик. Она становится доступна пользователям только после загрузки пакета и latest.json. Уже опубликованный выпуск не перезаписывается; для нового кода нужен новый номер версии.

Пользователям достаточно нажать «Проверить» → «Установить обновление», либо запустить Update.cmd. Полный архив с базой нужен только для переноса личного каталога на другой компьютер.

## Проверки без личных данных

В новом исходном коде нет data/. Поэтому проверки реальных прайсов и первоначального каталога пропускаются, если этих файлов нет на компьютере. Остальные проверки используют временные данные и работают самостоятельно.

Никакие персональные токены не записываются в проект. Выпуск в GitHub Actions использует штатный временный GITHUB_TOKEN с правом записи содержимого только для задания публикации.
